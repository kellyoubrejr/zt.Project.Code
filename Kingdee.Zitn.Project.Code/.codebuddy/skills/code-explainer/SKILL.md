# 代码解释器

## 概述
本skills为C#代码提供全面的解释服务，包括逻辑原理、运行流程、架构设计和业务规则说明，帮助开发者快速理解代码。

## 触发条件
当用户进行以下操作时自动触发：
- 理解代码逻辑原理
- 分析代码运行流程
- 学习代码架构设计
- 了解业务规则实现

## 使用方式

### 1. 基本用法
```
/Explain [文件路径]
```

### 2. 带参数用法
```
/Explain [文件路径] --focus [关注点]
```

### 3. 示例
```
/Explain ./plugin/PO/PoAuditToBPMHT.cs
/Explain ./Util/Tools.cs --focus 工具方法
/Explain ./Interface/ToMES/MesService.cs --focus 接口设计
```

## 解释维度

### 1. 逻辑原理 (logic)
- **内容**：代码的核心逻辑和算法原理
- **分析**：数据流、控制流、业务规则
- **重点**：关键算法、设计模式、架构思想

### 2. 运行流程 (flow)
- **内容**：代码的执行流程和调用链
- **分析**：方法调用顺序、事件处理流程、生命周期
- **重点**：入口点、关键步骤、异常处理

### 3. 架构设计 (architecture)
- **内容**：代码的整体架构和设计思想
- **分析**：模块划分、依赖关系、扩展点
- **重点**：设计模式、架构原则、可维护性

### 4. 业务规则 (business)
- **内容**：代码实现的业务规则和逻辑
- **分析**：业务流程、数据验证、状态管理
- **重点**：业务约束、规则引擎、流程控制

### 5. 技术细节 (technical)
- **内容**：代码使用的技术特性和实现细节
- **分析**：框架特性、API使用、性能优化
- **重点**：技术选型、实现技巧、最佳实践

## 解释示例

### 示例1：解释插件逻辑
```
/Explain ./plugin/PO/PoAuditToBPMHT.cs --focus 逻辑原理
```

**解释内容**：
```
## 概述
这是一个采购订单审核服务插件，用于将审核通过的采购订单推送到BPM系统。

## 核心逻辑
1. **触发条件**：当采购订单状态变为"已审核"时触发
2. **数据收集**：从当前单据中提取采购订单数据
3. **格式转换**：将金蝶数据格式转换为BPM要求的格式
4. **接口调用**：通过HTTP接口推送到BPM系统
5. **结果处理**：处理BPM返回结果，更新单据状态

## 执行流程
1. 用户点击"审核"按钮
2. 系统调用OnPrepareOperateOption方法
3. 执行BeginOperationTransaction开始事务
4. 在事务中执行数据推送逻辑
5. 根据推送结果提交或回滚事务

## 关键实现
- 使用BpmService封装HTTP调用
- 使用CustomLog记录推送过程
- 使用SendMsg发送成功/失败通知
- 使用DBUtils更新单据状态

## 设计思想
采用"操作服务插件"模式，将审核逻辑与业务逻辑分离，通过事件驱动的方式实现松耦合。
```

### 示例2：解释工具方法
```
/Explain ./Util/Tools.cs --focus 工具方法
```

**解释内容**：
```
## 概述
这是一个工具类，提供常用的数据处理方法，确保项目数据处理的一致性和安全性。

## 核心工具方法
1. **SafeStr**：安全获取字符串值，避免null引用异常
2. **Sql**：SQL字符串安全处理，防止SQL注入
3. **Str**：通用字符串转换，处理null值

## 设计原则
1. **防御性编程**：所有方法都考虑null值和边界情况
2. **一致性**：统一的数据处理方式，避免重复代码
3. **安全性**：防止SQL注入等安全漏洞
4. **可读性**：方法命名清晰，功能明确

## 使用场景
- 从数据库查询结果中安全获取字段值
- 构建SQL查询时防止注入攻击
- 外部数据转换为内部类型
- 配置文件和参数处理

## 最佳实践
1. 始终使用SafeStr处理可能为null的字符串
2. 构建SQL时使用Sql方法转义特殊字符
3. 使用Str方法进行通用的字符串转换
```

## 常见问题

### Q1: 解释会暴露敏感信息吗？
A1: 不会，解释只分析代码逻辑，不暴露敏感数据、密码、密钥等信息。

### Q2: 支持哪些C#版本？
A2: 支持.NET Framework 4.8及以上的C#语法，包括最新特性。

### Q3: 如何处理复杂代码？
A3: 会分层次解释：概述→核心逻辑→详细实现，并提供代码导航建议。

### Q4: 能否解释第三方库代码？
A4: 可以解释项目中使用的第三方库调用，但不会深入第三方库内部实现。

### Q5: 解释会随代码更新吗？
A5: 每次执行都会重新分析当前代码，确保解释与最新代码同步。
